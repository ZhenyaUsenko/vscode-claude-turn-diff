# claude_code
Claude Code runs shell hooks configured under "hooks" in ~/.claude/settings.json. Each hook receives a JSON payload on stdin carrying session_id and transcript_path and, from Claude Code 2.1.196, prompt_id.
UserPromptSubmit fires when the user submits a prompt. It also fires when a message queued during a running turn, or a background command that finished, is handed to the running turn; those payloads carry the running turn's prompt_id, while a genuine new prompt carries a fresh one.
PreToolUse fires before each tool call with tool_name and tool_input. Edit and Write carry tool_input.file_path, NotebookEdit carries tool_input.notebook_path, and Bash carries the command to run.
Stop fires when the main agent finishes a turn. StopFailure fires when a turn ends on an API error. Neither fires when the user interrupts a turn with Escape. Payloads sent from inside a subagent carry agent_id; the main agent's payloads never do. A subagent that dies on an API error raises StopFailure under the main session.
Claude Code writes a JSONL transcript per session at ~/.claude/projects/<key>/<session_id>.jsonl, where <key> is the directory the session started in with every character other than ASCII letters and digits replaced by "-". Each line is a JSON object with a type such as user, assistant, queue-operation, last-prompt or file-history-snapshot. Assistant entries carry message.stop_reason, one of end_turn, tool_use, pause_turn, max_tokens, stop_sequence or refusal; tool_use and pause_turn mean the turn continues. A user interruption is a user entry whose text starts with "[Request interrupted by user", usually followed by bookkeeping entries. Entries written by subagents carry isSidechain: true.

# vscode
The command vscode.changes takes a title and a list of [resourceUri, beforeUri, afterUri] triples and opens a multi-file diff editor as a preview tab; the next preview to open replaces it. Executing workbench.action.keepEditor right afterwards pins the active editor as a regular tab. An undefined beforeUri renders the entry as an added file and an undefined afterUri as a deleted file; the editor marks an entry as a rename when beforeUri.path and afterUri.path differ.
A file system provider registered for a scheme serves readFile and stat for uris of that scheme. When readFile throws FileNotFound for a uri whose text model is already loaded, the editor keeps the text it has; when it returns empty bytes, the editor shows an empty file.
workspace.workspaceFolders lists the open folders and is undefined when none is open. workspace.createFileSystemWatcher(pattern) returns a watcher with dispose(). VS Code watches files inside the workspace on its own but not files outside it.

# git
git write-tree writes the current index as a tree object and prints its hash. With GIT_INDEX_FILE set to a copy of the index, git add -u and git add -f stage into that copy and leave the real index untouched.
The index records each file's size and mtime. git does not re-read a file whose size and mtime match its index entry, except when the entry's mtime is not older than the index file's own mtime, which marks the entry as racily clean and forces a re-read.
git diff --name-status -z -M prints, for each change, a status letter followed by the path, each NUL-terminated; for a rename (status R) or copy (status C) the old path is followed by the new path. Rename detection pairs a deleted path with an added path of similar contents.
git cat-file --batch -z reads NUL-terminated object names such as <tree>:<path> from stdin and prints for each a header line "<hash> blob <size>" followed by the contents and a newline, or "<name> missing" when there is no such object.
git ls-files -o --exclude-standard -z lists untracked, non-ignored paths, NUL-separated.

# test_harness
In the tests HOME is a fresh temporary directory. The vscode module is a stub that records every executeCommand call with its command, title and resources, records every createFileSystemWatcher call as a watcher object with a disposed flag, and stores the registered file system provider. Tests drive the extension by calling handleTurn(mode, project, payload, workspaceDirs) directly with mode "begin", "arm" or "end", or through the hook script against a running server, and render by calling showLastTurn({ force: true }).
A turn in the tests is: handleTurn "begin" with session_id and prompt_id, handleTurn "arm" with the same ids (a further "arm" may carry tool_input.file_path for a file outside every repository), file changes, then handleTurn "end" with the session_id. The project key is derived from the repository directory the same way Claude Code derives its transcript directory key.
